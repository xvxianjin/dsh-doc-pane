# dsh-doc-pane

在 DSH Web GUI 的右栏里打开、直接编辑当前会话正在改的 Markdown 文档。选中文字交给模型，它判断是改写还是回答：改写直接落进文档并高亮成待确认，点一下高亮可以接受、撤销或就此提意见。每次请求都带上这个会话里已经聊过的内容作为背景。

## 用法

1. 打开一个会话，点会话标题右侧的「文档」按钮（`conversation.session.header.actions`）。
2. 文档面板作为右栏的一个标签页打开（和「开始 / 文件 / Git」那些标签并排，不遮挡中间的对话）。打开哪篇文档只看两件事：**从对话里的文档链接点进来，就看那个文档**；**点「文档」按钮进来，就看列表**——不会有「agent 正在改哪个就看哪个」的自动跳转。列表显示该会话工作目录里最近修改的 Markdown（最新的在最上面），点一个才开始编辑。
2b. 中间对话里点开一个 `.md` / `.txt` 链接，也会直接在这个面板的标签里打开那个文件，标签标题就是文件名。做法是认领整条地址类型（`dsh-resource://file/**/*.md` 等）：同档位里按匹配到的规则长度排序，这比 `dsh-better-sidebar` 的文件类型（`dsh-resource://file/**`）长，所以排在它前面。面板从地址里拆出路径和会话再打开；万一右栏没把地址交给标签内容，面板会退回显示最近修改列表。
3. 想看别的文档：把路径粘到列表上方的输入框里回车。是**文档**就打开它，是**文件夹**就切到那个文件夹的最近修改列表（绝对路径、相对工作区的路径都行）。也可以点「打开文件夹…」用系统选目录框挑一个目录；「回到工作区」退回会话工作目录。
4. 打开就是**可以直接改的文档**（类似飞书文档），没有单独的编辑页；头部留一个「源码」开关，需要看原始 Markdown 时切过去。
   - 文档视图由内置的编辑内核驱动（ProseMirror，`vendor/editor.js`，宿主通过 `/dsh-doc-pane/api/vendor/editor.js` 提供）：撤销/重做、中文输入法、三档列表缩进、表格里 `Tab` 跳格（最后一格再按一次会追加一行）、拖动可以框选多个单元格并按 `Delete` 清空内容、在单元格开头按退格不会把表格并掉、单元格宽度按列均分不再被内容挤扁、单元格内拖选文字就是普通的文字选区（不会整格选中，也不会把光标挡在表格外）、代码块内换行，都由内核负责，面板不再自己维护一套编辑状态。
   - 直接在上面打字，排版即时生效：`##` 加空格变二级标题（`#`…`######` 同理），`-` 或 `*` 加空格变无序列表，`1.` 加空格变有序列表，`>` 加空格变引用，三个反引号变代码块，`---` 回车变分隔线。
   - 行内标记也是即时的：打出 `**加粗**`、`*斜体*`、`` `代码` ``、`~~删除线~~`、`[链接](url)` 收尾就变成对应样式。粘贴只取纯文本，不带外部样式。
   - 快捷键：`Ctrl+Z` / `Ctrl+Shift+Z` 撤销重做，`Ctrl+B` 加粗、`Ctrl+I` 斜体、`Ctrl+Shift+X` 删除线，`Ctrl+Alt+1..3` 变标题，`Ctrl+Shift+7/8` 变有序/无序列表，`Tab` / `Shift+Tab` 增减缩进。
   - 停止输入 1.2 秒自动保存，`Ctrl+S` 立即保存。排版样式不变：标题层级、列表、引用、表格、图片、任务清单，代码块带语言标签。内核不可用时会自动退回内置的可编辑视图，功能照旧（只少撤销栈）。
5. 面板不会被别的对话抢走：你在看 A 篇文档时切换到另一个正在改文档的对话，面板仍然停在 A 篇（读取、保存、对话都继续用它所属的那个会话的工作目录）。这篇文档属于另一个会话时，头部会出现「回到当前会话」：点一下关掉它、回到当前对话的文档列表（只是列表，不会替你打开文件）。

6. 字号不合适就用头部的 `−  110%  +` 缩放：点百分比回到 100%，`Ctrl + 滚轮` 可以在面板上直接调；缩放会同时作用于正文、代码、表格、编辑区和底部对话区（不会把面板撑出右栏），选择会被记住。宽屏首次打开默认 115%。
7. 面板底部是对话区，和中间的聊天一样只有一个输入框，没有「改写 / 询问」模式：直接说「这段精简一下」它就改，问「这句话什么意思」它就答，判断交给模型。输入框在一张独立的白色卡片里（灰色底衬把对话区和文档分开）：卡片上方是引用，下方一排工具可以选择**模型**（默认跟随会话，也可指定 deepseek-v4-pro 等）和**技能**（可多选，最多 4 个，选中的技能显示成可移除的标签）。对话区在还没有消息时只占一张卡片的高度，不挤占文档；发出第一条后出现对话记录，此时可以拖动它上边缘的横条调高/调低，高度会被记住。
8. 技能和中间的对话一样由模型自己判断要不要用：每次请求都会带上技能目录（名字 + 一句说明），它觉得需要时会回一个 `{"kind":"skill","names":[…]}`,面板自动把技能全文补进去再问一次（最多两个，只有真用到才多一次往返）。你手动勾选的技能则一定会带上，并显示成标签。区别是技能只提供说明文本，面板不执行技能里的脚本或工具（它是一次模型调用，不是完整的 agent 会话）；需要跑脚本的活儿还是交给中间的对话。
9. 在**文档里**选中文字，输入框上方会出现一条引用（可点 × 取消，在文档里点一下空白处也会取消），这条引用会随消息一起发过去；模型按它决定是改写这段还是回答关于它的问题。要改写时，新文字**直接写进文档并保存**，改动的那段变成「待确认」高亮，对话里只留一句「已应用并保存」——不再有要先点接受的 diff 卡片。**选中的是位置，不是文字**：内置视图渲染时每一段、每个行内片段都带着它在源码里的偏移（`data-src`），从标题选到代码块再选到下一段也能准确落在源码的对应区间；换到编辑内核后没有这层偏移，就用「选区所在块 + 可见文字 + 附近位置」定位（同一句话出现多次时取离当前块最近的）。两边都不要求文字一模一样：会跳过 `**`、代码块语言标注行、表格的 `|`、重复成 `## ##` 的标题标记；仍然定位不到时只是不产生引用，不会弹报错。文档在面板里统一按 LF 编辑、保存时按原文件的换行写回，所以 CRLF 文件的位置也不会错。改动片段里带 `code`、**加粗** 这类行内标记，或者一次改了好几段时，会按段落逐块标成待确认（高亮落在整块文字上），点哪一块都能打开同一份菜单。**删除**用的也是建议模式那套：引用那段说「删了」，模型回一个空替换，面板把那条内容删掉——整行是标题或列表项时连 `## `、`- ` 标记一起删，空行不会留下两条；同时**把删掉的字以红色删除线放回原处**（和 Google Docs / 飞书的建议模式一样，删掉的内容还能看见），点它浮出「接受 / 拒绝并还原」：接受就真的消失，还原会把原文一字不差地放回原位（连换行一起）。删掉的是整行时，这条删除线单独占一行，就在原来那一行的位置。引用的是**标题**时，删掉的不是那一行标题，而是整个小节（从这个标题起，到下一个同级或更高级标题之前），后面的标题不会变成空壳；删除线只显示一小段摘要（首行加省略号），点它仍能一字不差地还原整节。选中文字的过程中不会误开高亮菜单（选择优先）。
10. agent（或别的窗口）在面板打开期间改了文件，重新载入后**改动过的行会高亮成待确认**：在预览里点一下高亮，浮出「接受 / 拒绝并还原 / 批注」——接受就消掉这一处；拒绝并还原把那一段恢复成改之前的原文并保存；批注把这段填进输入框上方的引用，接着就能说怎么改。编辑视图里把光标放进那段文字同样算确认，左侧还有一条色带；头部「待确认 N」可以一次全部标为已读；新的一批改动会自动滚到第一处。高亮不会写进文件，也不会永久留在文档里。标记按文件记在浏览器本地（`localStorage`，只存改动片段、原片段和位置）：重启 DSH 后打开同一篇、并且文件没再变过，待确认标记会回来；文件一变就按新内容重新算，不会留下过期的标记。
11. 请求都会附带本会话最近的对话内容和面板里之前的往来，模型据此理解文档的来龙去脉；`Ctrl+S` 保存；右栏自分栏宽度、关闭标签由右栏自己负责。

面板里的文件是磁盘上的真实文档，保存会直接写入；如果 agent 在面板打开期间又改了同一个文件，面板每 6 秒检查一次并在没有未保存修改时自动刷新，有冲突时保存会提示。工作区之外的文档也能打开、编辑，只限制 Markdown / 纯文本（`.md` `.markdown` `.mdx` `.txt`）。

面板从不自己打开文档：切会话、切目录、开面板都只列列表，只有「点链接」「点列表里的一项」「粘路径回车」这三种明确动作才会打开文件。

## 结构

| 文件 | 作用 |
| --- | --- |
| `index.js` | Host half：注册 `/dsh-doc-pane/api/{health,recent,stat,read,write,rewrite,chat,models,skills}` 路由，按会话解析根目录、扫描 Markdown（可指定任意目录）、读写文件、调用 `llm.stream` 做改写/对话，并用 `sessionQuery.readSurface` 取对话背景、用 `skills` 服务拼技能说明 |
| `client.js` | Browser half：右栏标签类型 `doc-pane` + 标签面板 + 会话标题栏按钮：可直接编辑的文档视图（ProseMirror 内核 + Markdown 与 DOM 互转）、源码视图、待确认高亮与高亮菜单、对话区都在这里 |
| `vendor/editor.js` | 预构建的编辑内核（ProseMirror，约 320 KB，`window.DshDocEditor`），由宿主路由按需提供给页面；改动它要重建，见下 |
| `tools/editor/` | 内核的源码与构建脚本（`entry.js`、`build.mjs`、`smoke.cjs`、依赖已锁版本），只在改内核时需要 |
| `cordis.patch.yml` | 把 `dsh-doc-pane` 插入 profile 的 Cordis 配置 |
| `recover-profile.cmd` / `recover-profile.ps1` | DSH 起不来时的急救脚本：从备份恢复 `cordis.patch.yml`，并把这个插件从 profile 的 bundles 里摘掉，让软件能重新打开 |

面板挂在右栏的方式：`ctx.sidebarRightTabs.register({ id, kind: 'doc-pane', patterns: ['dsh-resource://file/**/*.md', …], priority: 'extension', canOpen, title })` 声明一个标签类型，标签内容注册在 `sidebar.right.pane.tab`（key 与类型 id 相同），标题栏按钮调用 `ctx.sidebarRight.openTab('doc-pane')`。带 `patterns` 后它同时接管对话里的文档链接：右栏按地址挑类型，同档位比较匹配到的规则长度（我们 28–33 字符，`dsh-better-sidebar` 的 `dsh-resource://file/**` 只有 23），`extension` 一档本身又高于自带文档预览的 `fallback` 档。

地址怎么交到面板里：右栏并不会把地址注入标签内容，所以面板在 `ctx.get('sidebarRight')` 上把交地址的几个入口都包了一层——`openResource(address)`、`placeResource(session, actions, address, options)`、`openResourceIn(pane, address, options)`（不同的调用方走的不一定是同一个）：点到文本类地址时，先把路径/会话记进面板模块的 `visibility.link`（带自增序号，避免同一毫秒的两次点击被当成同一次），再直接用 `openTab('doc-pane')` 打开自己的标签（不再交给地址排序，避免启动早期类型还没注册时被别的插件接走）；非文本地址原样放行。`title(address)` 里也会顺手记录一次地址，作为兜底。面板订阅这个记录，用 `parseFileAddress` 拆出路径与会话后直接打开；标签还开着上一次的文档时，新记录会把它换掉。

根目录解析顺序：`config.root` → 会话工作目录（宿主 `workingDirectory.ensure(agent)`）→ 最新活跃会话的工作目录 → `workingDirectory.defaultDirectory` → `process.cwd()`。没有会话时不再落到 profile 目录。可选配置：

```yaml
- id: dsh-doc-pane
  name: '@local/dsh-doc-pane'
  config:
    root: 'C:/path/to/notes'
```

## 开发

改完 `index.js` 需要在插件管理里禁用再启用该插件才会重新加载 Host half；重启 DSH 一次也会拿到新版本。`client.js` 同样在重启后生效。

改编辑内核（快捷键、schema、待确认高亮的位置计算都在里面）：

```bash
cd tools/editor
npm install          # 只在第一次、或升级依赖后
node build.mjs       # 重新生成 ../../vendor/editor.js（提交这个产物）
node build.mjs --test # 顺便跑 jsdom 冒烟测试
```

`vendor/editor.js` 是入库产物：插件运行时没有构建步骤，宿主直接把它当静态脚本发给页面。

## 起不来的时候

崩溃弹窗里第三个按钮（「禁用第三方插件、备份 profile patch 并重启」）在恢复时会把 `cordis.patch.yml` 截断成约 700 字节，丢掉 `agent-default-model`、`web-ui-pet`、`dsh-ops-file`、`dsh-ops-shell` 这些块。中间那个「重启」只是在同一份配置上重启，如果崩溃原因还在就会一直进不去。

所以：**先退出 DSH**，再双击 `recover-profile.cmd`。它会

1. 把当前的 `cordis.patch.yml` 另存为 `cordis.patch.yml.bak-before-recover-<时间戳>`；
2. 用目录里最新、且大于 1000 字节的 `cordis.patch.yml.bak-*` 覆盖回去（被截断的那份只有几百字节，不会被选中）；
3. 从 `package.json` 的 `dsh.profile.bundles` 里摘掉本插件（`dependencies` 里的 `link:` 保留），然后重新打开 DSH 即可。

插件重新装回：`plugin_manager install_bundle` 指向本目录。Host half 的路由注册整段包在 try/catch 里，注册失败只会少一个接口，不会让激活失败。

客户端半区别声明任何 `inject`：声明了服务又没就绪时，Cordis 会把条目停在 `loading`，而 Web 启动审计会把这种情况当成致命错误（`web boot: 1 entry did not activate`）。服务一律用 `ctx.get` 取，注册延后到服务出现时再做。
